# Бесполётные зоны в MultiUAV Planner

Документ описывает источники данных о бесполётных зонах, их формат и алгоритм обработки при планировании полётных заданий.

## Источники данных

Сервис использует два нормативных источника, устанавливающих ограничения на использование воздушного пространства:

| Приказ | Тип зон | Поведение планировщика |
|--------|---------|------------------------|
| **Приказ Минтранса России от 11.05.2022 № 172** (ред. от 23.01.2026) «Об установлении запретных зон» | Запретные зоны | Маршрут **не прокладывается**. Зона полностью исключается из области планирования. |
| **Приказ Минтранса России от 24.11.2025 № 410** «Об установлении постоянных зон ограничения полетов и временных зарезервированных зон ограничения полетов» | Зоны ограничения полётов | Маршрут **прокладывается**, но пользователю выдаётся предупреждение с идентификатором зоны, её описанием и ссылкой на подробную информацию. |

Оба приказа размещены на портале [ГАРАНТ](https://base.garant.ru):

- Приказ № 172: https://base.garant.ru/404831269/53f89421bbdaf741eb2d1ecc4ddb4c33/
- Приказ № 410: https://www.garant.ru/products/ipo/prime/doc/413384888/#30

## Формат данных

Зоны хранятся на стороне бэкенда в виде JSON-массива. Каждая зона описывается следующей структурой:

    {
      "id": "ULR1",
      "type": "polygon",
      "altitude": {
        "min_m": 0.0,
        "max_m": 3048.0,
        "reference": "FL"
      },
      "schedule": {
        "type": "permanent",
        "description": "Круглосуточно"
      },
      "coordinates": [
        [60.06861111111112, 30.378055555555555],
        [60.056666666666665, 30.384999999999998],
        ...
      ],
      "exceptions": "Не распространяется на воздушные суда..."
    }

> **Примечание:** для круговых зон используются поля `center` и `radius_km` вместо `coordinates`. Поле `exceptions` присутствует только у некоторых зон и содержит нормативный текст об исключениях.

### Хранение запретных зон

Запретные зоны хранятся в **упрощённом виде** — только геометрия (полигон или круг). Для них не используются поля `altitude`, `schedule` и `exceptions`, так как они полностью запрещают полёты и не требуют дополнительной информации. Полный формат, описанный выше, применяется для зон ограничения полётов, где важно указать высоты, расписание и исключения.

## Обработка зон при планировании

### Запретные зоны (Приказ № 172)

Запретные зоны загружаются в планировщик как жёсткие геометрические препятствия. При построении маршрута для каждого БВС выполняется проверка пересечения сегментов маршрута с полигонами (или кругами) запретных зон. Если маршрут пересекает запретную зону, планировщик исключает такие траектории из рассмотрения и строит обходной путь.

Запретные зоны не передаются в запросе API — они уже хранятся на стороне бэкенда и учитываются автоматически.

### Зоны ограничения полётов (Приказ № 410)

Зоны ограничения полётов не являются жёсткими препятствиями: маршрут через них **разрешается**. Однако после расчёта полётного задания планировщик проверяет, какие зоны ограничения были затронуты, и формирует массив `warnings` в ответе API.
