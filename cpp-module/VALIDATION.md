# Финальная проверка — 24 сентября 2026

## Среда и сборка

Linux x86_64, GCC/G++ 13.3, C++17, Release. Выполнена сборка в новом каталоге
`build-clean`, без reuse объектных файлов предыдущих сборок. Предупреждений
компилятора нет. CMake использует vendored-зависимости, без FetchContent.

- CTest: **2/2 PASS**, smoke + полный regression, 6,46 с.
- Приёмочный validator: **54 проверки PASS**. PASS для отрицательного сценария
  означает ожидаемый диагностический отказ, а не построенный маршрут.
- ASan + UBSan: **47 JSON-сценариев + 10 некорректных/крайних входов**, без
  обнаруженных ошибок. LeakSanitizer отключён: среда не поддерживает его ptrace.
- 8 одновременных вызовов C ABI: одинаковые детерминированные результаты.
- Интеграция с неизменённым backend: HTTP 200 + PlanResponse для корректного
  запроса; 422 для отсутствующего GSD/LiDAR/MultiPolygon; предсказуемый HTTP 500
  для отказа планировщика (так устроен существующий backend).
- Режим без внешнего файла зон: библиотека использовала встроенную копию,
  сохранила валидный результат и выдала соответствующее предупреждение.
- Все исходные файлы вне cpp-module сверены с исходными SHA-256: изменений нет.
- Копия no-fly-zons побайтово совпадает с исходным frontend JSON.

Docker Engine в среде отсутствует: реальная сборка Docker-образов и запуск
compose не выполнялись. Команды проверки на ПК приведены в README.md.

## Проверенные ограничения

В каждом успешном сценарии независимо проверены JSON, отсутствие NaN/inf,
модель backend PlanResponse, ссылки UAV/type/camera/start/landing, соответствие
route и waypoints, последовательность действий и времени, параметры камеры и
GSD, положительный photo_distance с продольным перекрытием 50%, границы высоты,
набор/снижение, скорость, полная длина вылета и радиус от базы. Геодезическая
длина дополнительно рассчитана по эллипсоиду WGS84 с pyproj.Geod.

Shapely проверяет **все отрезки**, включая транзит, на пересечения исходных
полигональных/круглых NFZ и отверстий. Съёмочные отрезки проверяются на
принадлежность исходной области. Для самолётных маршрутов проверены радиусы
по тройкам последовательных точек. Временные конфликты проверяются поиском
минимального 3D расстояния между движущимися точками на каждом перекрывающемся
по времени интервале; это не проверка только дискретных waypoint-моментов.

Проверены повторные вылеты, обслуживание между ними и отсутствие
неучтённой смены базы одним UAV. Включены простой/невыпуклый полигон,
обратный порядок вершин, отверстия, пересекающиеся NFZ, Polygon/MultiPolygon
через C ABI, несколько аппаратов, фиксированное крыло, численно некорректные
входы, невозможные range/home/time/GSD ограничения и явный flight-time limit.

## Большой сценарий

Площадь: **100.02 км²**, **10 БВС**, полигональные и
круглые NFZ. Расчёт через C ABI с разбором JSON: **2.5814 с**;
вместе с независимой валидацией: **3.262 с**.

Результат: **18 вылетов**, **1882 waypoints**, суммарный
налёт 946538.0 м. Время выполнения операции: 8206.71 с.
Это длительность полётов по расписанию, её нельзя путать со временем расчёта.

Синтетический вход явно задаёт range=60 000 м, home radius=25 000 м, 10 БВС,
GSD=5 см/пиксель, без конечного срока операции. NFZ этого теста — исходная база
плюс явно добавленные тестовые препятствия; рабочий файл зон не изменяется.
Все параметры доступны в `tests/generated/100km2_ten_uavs_with_nfz_request.json`;
тестовая база — `tests/generated/zones.json`.

Покрытие кадрами исходной площади в этом сценарии: 97.008%.
Непокрытая часть включает исключённые запретные зоны/отступы. Полное покрытие
исходного контура не заявляется. Аналогичный большой тест без препятствий
покрыл 100% проверенной прямоугольной области.

## Исходные test-data

Все **10 оригинальных файлов не содержат обязательный gsd**. Они проверены
без исправлений: ожидаемый отказ. Затем каждый отдельно проверен с явно
заданным тестовым `gsd=3` см/пиксель. Это не скрытый default в модуле.

| Исходный файл, с тестовым GSD=3 | Фактический результат |
|---|---|
| `15_uavs.json` | План: 13 вылетов, 13 БВС; все проверки пройдены |
| `area_too_large.json` | Отказ: выход за предел 50 км локальной модели |
| `base_request.json` | План: 1 вылетов, 1 БВС; все проверки пройдены |
| `lots_of_holes.json` | Отказ: эвристика не нашла безопасный самолётный маршрут |
| `one_of_starts_from_no_fly_zone.json` | План: 1 вылетов, 1 БВС; все проверки пройдены |
| `regular.json` | План: 2 вылетов, 2 БВС; все проверки пройдены |
| `start_from_no_fly_zone.json` | Отказ: недопустимый старт/невозможный маршрут |
| `start_too_far.json` | Отказ: старт за пределом 50 км локальной модели |
| `unreachable_area.json` | Отказ: отсутствует доступная съёмочная область |
| `with_no_fly_zone.json` | План: 2 вылетов, 2 БВС; все проверки пройдены |

Сценарий lots_of_holes остаётся известным ограничением эвристики. Он не
объявляется математически невозможным. Общие ограничения модели, консервативная
геометрия, отсутствие параметров LiDAR/эндюранса, ограничение ±65°/50 км и
проблема многовылетного экспорта существующего frontend перечислены в README.md.

## Машиночитаемые результаты

- `tests/validation_report.json` — все приёмочные случаи и измеренные метрики.
- `tests/integration_report.json` — статусы настоящего backend и fallback зон.
- `tests/sanitizer_report.json` — отдельные native-сценарии под ASan/UBSan.
- `tests/clean-build.log`, `tests/ctest.log` — финальная сборка/CTest.
- `tests/original_readonly_sha256.json` — исходные хэши неизменяемых файлов.
- `tests/generated/*` — запросы и ответы воспроизводимых проверок.

Результаты гарантируют перечисленные проверки в данной модели и на данных
сценариях, а не корректность произвольного реального полёта или глобальный optimum.
